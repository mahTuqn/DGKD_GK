# Local API and production-preview DAST run

With Docker Desktop running, run `npm run scan:dast:api` from the repository root. The script runs three scans sequentially in separate fresh Compose projects, each with a unique name and database volume:

1. **Unauthenticated API:** starts PostgreSQL, migrations, and API; requires `/api/auth/me` to return 401 before scanning.
2. **Authenticated API:** starts a separate PostgreSQL/API stack; requires the seeded Admin login and `/api/admin/summary` preflight to return 200 before scanning.
3. **Production preview:** starts a third PostgreSQL/API/migrations/web stack, seeds fresh demo data, and scans the production-built preview at `http://web:8080` from that project's private network. The web health and root paths must return 200; `/api/` is excluded because the two API scans cover it separately.

The runner verifies that only the expected Compose services are present in each stack; the worker is never started. PostgreSQL and preview host ports are selected as loopback-only ephemeral ports, while ZAP reaches the services through their private Compose network. Each project and its volume are removed after its scan. Run-specific API and preview reports are kept under `reports/generated/dast/`; any Admin JWT in the authenticated report or logs is redacted.

The default DAST-only seed account is `admin@cinema.local` / `CinemaAdmin123!`. Override it with `DAST_ADMIN_EMAIL` and `DAST_ADMIN_PASSWORD` if the seed changes. The ZAP image is pinned by default to `ghcr.io/zaproxy/zaproxy:2.17.0@sha256:030d3df57735dacbb83464854758e674dd9ad01d79d12a129a8e58b1fd384238`; set `ZAP_IMAGE` to another image reference that includes an explicit SHA-256 digest to change it. The image tag and digest were checked against the [official ZAP GHCR package versions](https://github.com/zaproxy/zaproxy/pkgs/container/zaproxy/versions?tag=2.17.0). The token is created in memory and passed to the authenticated API ZAP container through its process environment; it is not written to the plan, command arguments, or report. ZAP containers mount only the plan directory and shared OpenAPI docs read-only, plus the DAST report directory writable.

The script validates generated project/container names and refuses to reuse existing resources. It never targets the normal Compose project. By default, each temporary project and its volume are removed after its scan. Set `DAST_KEEP_VOLUMES=1` to remove the run-owned containers/networks while preserving the uniquely named PostgreSQL volumes. If Docker is interrupted during cleanup, remove only the exact `cinema-dast-<run-id>-unauth`, `cinema-dast-<run-id>-auth`, or `cinema-dast-<run-id>-preview` project shown in that run's output; retain or remove its volumes only if they were created by that run and the operator has approved their disposition.
